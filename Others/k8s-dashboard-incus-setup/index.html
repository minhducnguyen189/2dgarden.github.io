    Comprehensive Guide: Web Dashboard (Headlamp) + metrics-server#

    This document covers adding a web UI to the cluster — Headlamp — plus metrics-server so the UI shows live CPU/RAM and kubectl top works. It is exposed with a NodePort reachable from the physical host's browser.

    Why Headlamp, not the Kubernetes Dashboard? The classic kubernetes/dashboard project was archived on 2026-01-21 and its Helm repo (kubernetes.github.io/dashboard) is offline. SIG-UI now ships Headlamp (kubernetes-sigs/headlamp) as the successor — actively maintained, lighter (a single Deployment, no Kong gateway), and plain HTTP (one less TLS warning behind a NodePort). See the Kubernetes blog, "From Kubernetes Dashboard to Headlamp" (2026-06-01).

    Part of a set. Build the HA masters, workers, and kcontrol admin box first. See ./incus-k8s-setup.md for the overview and current state.

    Prerequisite: a working cluster and the kcontrol box with kubectl + helm and the admin kubeconfig (control guide). Every command below is run from the Ubuntu host and dispatched into kcontrol with incus exec.

    Phase 1: metrics-server#

    The Dashboard's CPU/RAM graphs and kubectl top both read from the metrics.k8s.io API, which is served by metrics-server. It is not installed by default.

    Incus gotcha — kubelet serving certs. metrics-server scrapes each kubelet over HTTPS and, by default, verifies the kubelet's serving certificate. In this cluster those certs are self-signed, so verification fails and no metrics appear. The fix is the --kubelet-insecure-tls flag, baked in at install time below. (Acceptable here: the scrape stays on the private incusbr0 network.)

    incus exec kcontrol -- helm repo add metrics-server https://kubernetes-sigs.github.io/metrics-server/
incus exec kcontrol -- helm repo update

incus exec kcontrol -- helm upgrade --install metrics-server metrics-server/metrics-server \
  -n kube-system \
  --set 'args={--kubelet-insecure-tls}'

    Verify (give it ~30–60 s for the first scrape):

    incus exec kcontrol -- kubectl -n kube-system rollout status deploy/metrics-server
incus exec kcontrol -- kubectl top nodes

    kubectl top nodes returning CPU/MEM for all four nodes = success.

    Phase 2: Install Headlamp#

    Headlamp installs via Helm into its own headlamp namespace:

    incus exec kcontrol -- helm repo add headlamp https://kubernetes-sigs.github.io/headlamp/
incus exec kcontrol -- helm repo update

incus exec kcontrol -- helm upgrade --install headlamp headlamp/headlamp \
  --namespace headlamp --create-namespace

incus exec kcontrol -- kubectl -n headlamp rollout status deploy/headlamp

    First start is slow. The ghcr.io/headlamp-k8s/headlamp image is a few hundred MB; on a home link the initial pull can take several minutes (ContainerCreating). That's normal — kubectl -n headlamp get pods -w.

    Phase 3: Expose it as a NodePort#

    Headlamp's Service (headlamp) listens on port 80 (HTTP). Flip it to NodePort so the host browser can reach it on any node IP:

    incus exec kcontrol -- kubectl -n headlamp patch svc headlamp -p '{"spec":{"type":"NodePort"}}'
incus exec kcontrol -- kubectl -n headlamp get svc headlamp

    Read the 80:3XXXX/TCP port. In the running cluster this is 31293.

    Optional — pin it. NodePorts are auto-assigned (30000–32767) and survive reinstalls only if pinned. To fix it, add nodePort: 31293 under the port in the Service spec (kubectl -n headlamp edit svc headlamp).

    Phase 4: Create an admin user + login token#

    Headlamp authenticates with a ServiceAccount bearer token. Create a cluster-admin user and a long-lived token. The manifest lives in this repo as headlamp-admin-user.yaml:

    apiVersion: v1
kind: ServiceAccount
metadata: { name: admin-user, namespace: headlamp }
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata: { name: admin-user }
roleRef: { apiGroup: rbac.authorization.k8s.io, kind: ClusterRole, name: cluster-admin }
subjects:
- { kind: ServiceAccount, name: admin-user, namespace: headlamp }
---
apiVersion: v1
kind: Secret
metadata:
  name: admin-user
  namespace: headlamp
  annotations: { kubernetes.io/service-account.name: admin-user }
type: kubernetes.io/service-account-token

    Apply it and print the token:

    cat headlamp-admin-user.yaml | incus exec kcontrol -- kubectl apply -f -

# Long-lived token (from the Secret):
incus exec kcontrol -- kubectl -n headlamp get secret admin-user \
  -o jsonpath='{.data.token}' | base64 -d; echo
# (or a short-lived 1 h token: kubectl -n headlamp create token admin-user)

    ⚠️ cluster-admin = full control of the cluster. Fine for a single-user homelab; keep the token private. To scope down, bind a narrower ClusterRole.

    Phase 5: Open the dashboard#

    From the physical host's browser (the 10.177.167.x subnet is NAT'd, so this is reachable from the host only — not other LAN machines):

    http://10.177.167.228:31293        # knode1 — any node IP works

    Choose Token, paste the Phase-4 token, sign in. metrics-server populates the CPU/RAM gauges. Done.

    Verification#

    incus exec kcontrol -- kubectl top nodes                         # metrics live
incus exec kcontrol -- kubectl -n headlamp get pods,svc          # pod Running, svc NodePort
curl -s -o /dev/null -w '%{http_code}\n' http://10.177.167.228:31293   # from host → 200

    Troubleshooting#

    Symptom Cause / fix
    kubectl top empty, metrics-server logs show x509 errors --kubelet-insecure-tls missing — re-run the Phase-1 helm upgrade
    Headlamp pod stuck ContainerCreating for minutes Large ghcr.io image still pulling — kubectl -n headlamp describe pod to confirm Pulling (not ErrImagePull)
    Browser can't reach :31293 Use a node IP (.26/.33/.228/.118), not the LB; confirm svc type is NodePort
    A helm/image fetch stalls IPv6 is off on incusbr0; prefer IPv4 on the box via /etc/gai.conf → precedence ::ffff:0:0/96 100

    Uninstall#

    incus exec kcontrol -- helm -n headlamp uninstall headlamp
incus exec kcontrol -- kubectl delete ns headlamp
incus exec kcontrol -- kubectl delete clusterrolebinding admin-user
# metrics-server is independently useful; leave it, or:
# incus exec kcontrol -- helm -n kube-system uninstall metrics-server
