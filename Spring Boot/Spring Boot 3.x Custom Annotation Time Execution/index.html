    Custom Annotation For Method Execution Time (AOP)#

    What Is The Topic#

    • A very common cross-cutting concern is measuring how long a method takes to run — for performance monitoring, finding slow queries, or spotting regressions.
    • Doing it by hand (long start = System.currentTimeMillis(); ... ; log.info(...)) scatters timing code across every method you care about. That is exactly the code tangling and scattering problem that AOP solves (see Spring Boot 3.x AOP Introduction).
    • In this note we build a reusable custom annotation — @LogExecutionTime — that you simply place on any Spring bean method. An @Aspect intercepts those methods, times them, and logs the result. The business code stays clean.
    • We go step by step: a minimal working version first, then make it richer and configurable, then cover the important proxy caveats and how to test it.

    How It Works (The Big Picture)#

    • Three pieces collaborate:
    Piece Role
    @LogExecutionTime A marker annotation you put on methods you want timed. It carries no logic itself.
    The Aspect (@Around advice) Intercepts calls to annotated methods, runs the method, measures elapsed time, logs it.
    The Spring AOP proxy At runtime Spring wraps your bean in a proxy. Calls go through the proxy, which is where the aspect runs.
    • Crucial consequence of the proxy model: the aspect only triggers when the call comes from outside the bean (through the proxy). A method calling another @LogExecutionTime method on this will not be intercepted. More on this in Step 6.
    caller ──▶ [ Spring AOP Proxy ] ──▶ your bean method
                   │
                   └── @Around advice: start timer → proceed() → stop timer → log

    Project Setup#

    • Add the AOP starter (this brings in Spring AOP and AspectJ weaving support):
    <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>

    • That's all you need. Spring Boot auto-enables AspectJ auto-proxying when this starter is on the classpath — you do not need @EnableAspectJAutoProxy in a Boot app.

    • For logging we use SLF4J (the logging facade Spring Boot already ships with, backed by Logback). To avoid the boilerplate private static final Logger log = ... line, we use Lombok's @Slf4j annotation, which generates that field for us at compile time. Add Lombok:

    <dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <scope>provided</scope>
</dependency>

    @Slf4j just injects private static final org.slf4j.Logger log = LoggerFactory.getLogger(<EnclosingClass>.class);. If you prefer not to use Lombok, declare that field by hand — everything else in this note stays identical.

    Step 1 — Create The Custom Annotation#

    • The annotation is just a marker. The two meta-annotations decide where it can go and how long it lives.
    // LogExecutionTime.java
package com.example.demo.aop;

import java.lang.annotation.*;

@Target(ElementType.METHOD)          // can only be placed on methods
@Retention(RetentionPolicy.RUNTIME)  // must be visible at runtime for AOP to read it
public @interface LogExecutionTime {
}
    • Why these matter:
      • @Retention(RUNTIME) is mandatory — Spring inspects the annotation at runtime via reflection. With the default (CLASS) the aspect would never see it.
      • @Target(METHOD) restricts it to methods, giving a compile-time error if someone misuses it.

    Step 2 — Create The Aspect#

    • The aspect is a Spring bean (@Component) annotated with @Aspect. We use @Around advice because we need to run code before and after the method to bracket the timing.
    // LogExecutionTimeAspect.java
package com.example.demo.aop;

import lombok.extern.slf4j.Slf4j;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.springframework.stereotype.Component;

@Slf4j        // Lombok generates the SLF4J `log` field for this class
@Aspect
@Component
public class LogExecutionTimeAspect {

    // Pointcut: any method annotated with @LogExecutionTime
    @Around("@annotation(com.example.demo.aop.LogExecutionTime)")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {

        long start = System.nanoTime();
        try {
            return joinPoint.proceed();          // run the actual method
        } finally {
            long elapsedMs = (System.nanoTime() - start) / 1_000_000;
            String method = joinPoint.getSignature().toShortString();
            log.info("{} executed in {} ms", method, elapsedMs);
        }
    }
}
    • Line-by-line:
      • @Around("@annotation(...)") — the pointcut expression matches every method carrying our annotation.
      • ProceedingJoinPoint — unique to @Around; proceed() actually invokes the target method and returns its result.
      • We use System.nanoTime() (monotonic, immune to clock adjustments) and convert to milliseconds for readability.
      • The try/finally guarantees we still log the time even if the method throws — important for spotting slow failures. We don't catch the exception, so it propagates normally.

    Step 3 — Use It#

    • Annotate any Spring-managed bean method:
    // ProductService.java
package com.example.demo.product;

import com.example.demo.aop.LogExecutionTime;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @LogExecutionTime
    public Product getById(Long id) {
        // ... simulate work
        return repository.findById(id).orElseThrow();
    }
}
    • Calling productService.getById(1L) now produces a log line:
    INFO  c.e.demo.aop.LogExecutionTimeAspect : ProductService.getById(..) executed in 42 ms
    • That is the complete minimum viable version. Everything below makes it more useful.

    Step 4 — Add Richer Context To The Log#

    • ProceedingJoinPoint exposes a lot of metadata. Let's log the class, method name, and arguments, which makes the output far more actionable.
    import org.aspectj.lang.Signature;
import java.util.Arrays;

@Around("@annotation(com.example.demo.aop.LogExecutionTime)")
public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
    long start = System.nanoTime();
    boolean failed = false;
    try {
        return joinPoint.proceed();
    } catch (Throwable t) {
        failed = true;
        throw t;
    } finally {
        long elapsedMs = (System.nanoTime() - start) / 1_000_000;
        Signature sig = joinPoint.getSignature();
        String className = sig.getDeclaringType().getSimpleName();
        String methodName = sig.getName();
        String args = Arrays.toString(joinPoint.getArgs());

        log.info("{}#{}{} -> {} in {} ms",
                className, methodName, args,
                failed ? "FAILED" : "OK", elapsedMs);
    }
}
    • Sample output:
    INFO  ... : ProductService#getById[1] -> OK in 42 ms
INFO  ... : ProductService#getById[999] -> FAILED in 5 ms

    Step 5 — Make The Annotation Configurable#

    • Real usage wants options: a custom label, the time unit, and a warning threshold so only slow calls are flagged. Add attributes to the annotation.
    // LogExecutionTime.java
package com.example.demo.aop;

import java.lang.annotation.*;
import java.util.concurrent.TimeUnit;

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface LogExecutionTime {

    /** Optional label; defaults to the method signature. */
    String value() default "";

    /** Unit used to report the elapsed time. */
    TimeUnit unit() default TimeUnit.MILLISECONDS;

    /** Log at WARN level if the call takes longer than this many milliseconds. */
    long warnThresholdMs() default Long.MAX_VALUE;
}
    • Now bind the annotation instance in the advice so we can read its attributes. Note the second parameter LogExecutionTime annotation matched by name in the pointcut:
    import java.util.concurrent.TimeUnit;

@Around("@annotation(annotation)")        // bind the annotation by argument name
public Object logExecutionTime(ProceedingJoinPoint joinPoint,
                               LogExecutionTime annotation) throws Throwable {
    long start = System.nanoTime();
    try {
        return joinPoint.proceed();
    } finally {
        long nanos = System.nanoTime() - start;
        long elapsedMs = nanos / 1_000_000;

        TimeUnit unit = annotation.unit();
        long reported = unit.convert(nanos, TimeUnit.NANOSECONDS);

        String label = annotation.value().isBlank()
                ? joinPoint.getSignature().toShortString()
                : annotation.value();

        String unitName = unit.name().toLowerCase();

        if (elapsedMs > annotation.warnThresholdMs()) {
            log.warn("SLOW: {} took {} {} (> {} ms threshold)",
                    label, reported, unitName, annotation.warnThresholdMs());
        } else {
            log.info("{} executed in {} {}", label, reported, unitName);
        }
    }
}
    • Usage with attributes:
    @LogExecutionTime(value = "load-product", unit = TimeUnit.MILLISECONDS, warnThresholdMs = 200)
public Product getById(Long id) { ... }
    • Key technique: to read annotation values inside an aspect, name it in the pointcut (@annotation(annotation)) and declare a matching method parameter. Spring binds the actual annotation instance for you — no reflection needed.

    Step 6 — The Self-Invocation Caveat (Important)#

    • Because Spring AOP is proxy-based, the advice only runs for calls that go through the proxy. A common gotcha:
    @Service
public class ReportService {

    public void generateReport() {
        // ❌ this internal call does NOT trigger the aspect —
        //    'this' is the raw bean, not the proxy
        buildSection();
    }

    @LogExecutionTime
    public void buildSection() { ... }
}
    • buildSection() is called on this, bypassing the proxy, so no timing is logged. Workarounds:
      • Move the annotated method to another bean and inject it — the cleanest fix.
      • Self-inject the proxy (@Autowired private ReportService self;) and call self.buildSection().
      • As a last resort, enable @EnableAspectJAutoProxy(exposeProxy = true) and use ((ReportService) AopContext.currentProxy()).buildSection().
    • Also note: Spring AOP only advises Spring-managed beans, and only public methods are proxied by default (CGLIB). Annotating a private method or a plain new-ed object does nothing.

    Step 7 — Pointcut Variations#

    • The @annotation(...) pointcut is method-level. A few other useful forms:
    Pointcut expression Matches
    @annotation(com...LogExecutionTime) Methods annotated with @LogExecutionTime.
    @within(com...LogExecutionTime) All methods of a class annotated with it (put it on the type).
    execution(* com.example.demo.service..*(..)) Every method in the service package — useful to time a whole layer without annotating each method.
    @annotation(x) && execution(public * *(..)) Combine conditions with &&, ||, !.
    • For a "time everything in the service layer" policy, an execution(...) pointcut avoids touching each method; for opt-in precision, the custom annotation is better.

    Step 8 — Testing The Aspect#

    • You want to prove that (a) the annotated method still returns correctly and (b) the aspect actually fires. Load a minimal context with the real bean + aspect:
    import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.context.annotation.Import;

import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.aop.support.AopUtils.isAopProxy;

@SpringBootTest(classes = {
        LogExecutionTimeAspect.class,
        TimedComponent.class
})
@Import(org.springframework.boot.autoconfigure.aop.AopAutoConfiguration.class)
class LogExecutionTimeAspectTest {

    @Autowired
    private TimedComponent component;

    @Test
    void beanIsProxied_andMethodStillWorks() {
        // the aspect being applied means Spring wrapped the bean in a proxy
        assertThat(isAopProxy(component)).isTrue();

        // behavior is unchanged by the aspect
        assertThat(component.slowAdd(2, 3)).isEqualTo(5);
    }
}
    • To assert on the log output itself, attach a Logback ListAppender to the aspect's logger and verify a line was emitted. The @Slf4j-generated logger is named after the class, so we fetch it by LogExecutionTimeAspect.class:
    import ch.qos.logback.classic.Logger;
import ch.qos.logback.classic.spi.ILoggingEvent;
import ch.qos.logback.core.read.ListAppender;
import org.slf4j.LoggerFactory;

ListAppender<ILoggingEvent> appender = new ListAppender<>();
appender.start();
((Logger) LoggerFactory.getLogger(LogExecutionTimeAspect.class)).addAppender(appender);

component.slowAdd(2, 3);

assertThat(appender.list)
    .anySatisfy(e -> assertThat(e.getFormattedMessage()).contains("executed in"));
    • See Spring Boot 3.x JunitTest 5 for the broader testing toolkit (@SpringBootTest, MockMvc, slices).

    Best Practices#

    • Keep advice cheap. It runs on every annotated call; avoid heavy work (string building only when you actually log, etc.).
    • Use nanoTime, not currentTimeMillis, for durations — it is monotonic and unaffected by clock changes.
    • Always time in finally so slow failures are captured too; never swallow the original exception.
    • Mind the proxy boundary — internal self-calls won't be advised (Step 6).
    • Prefer Micrometer @Timed for production metrics. A custom aspect is perfect for learning and ad-hoc logging, but for real observability use Micrometer + Actuator, which exports timings to Prometheus/Grafana with percentiles and histograms.
    • Don't over-apply. Timing every method floods logs; annotate the boundaries that matter (controllers, service entry points, external calls).
